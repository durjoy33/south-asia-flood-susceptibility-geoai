# Publishing: GitHub, Zenodo and the manuscript

1. **Resolve data rights first.** Check the redistribution terms for `data/processed/SR_GEOAI_Flood_Master_Dataset.csv`. It contains georeferenced presence/background records and predictor attributes. If redistribution is not explicitly permitted, remove it from the public repository before the first commit and keep only `data/processed/README.md` and `DATA_DICTIONARY.csv` if the dictionary itself is redistributable.
2. Complete `data/processed/DATA_DICTIONARY.csv` and `docs/DATA_AND_LICENSING.md`: source, product/version, effective dates, native resolution, aggregation, units, licence and attribution for every predictor. Verify that the temporal period stated in the manuscript matches the rasters actually used.
3. Create a public GitHub repository named `south-asia-flood-susceptibility-geoai`. Upload the extracted repository contents to the repository root. Alternatively, use Git locally: `git init`, `git add .`, `git status` (inspect every staged file), `git commit -m "Initial research-code release"`, `git branch -M main`, `git remote add origin https://github.com/<USER>/south-asia-flood-susceptibility-geoai.git`, then `git push -u origin main`.
4. **Do not upload third-party rasters or raw inventory to GitHub or Zenodo unless their licences permit redistribution.** If a separate data archive is appropriate, include only materials you are entitled to distribute, with provider attribution and licence metadata.
5. Test the repository from a clean environment as far as practical. The static validation script checks notebook structure and code syntax; it does not run the full computationally intensive raster and model pipeline. Record the actual package versions after a successful environment setup.
6. Connect the GitHub repository to Zenodo only after the repository is public and its contents and licensing have been checked. Create a versioned GitHub release (for example, `v1.0.0`) and confirm that Zenodo has archived that release and issued a DOI.
7. Replace `[GITHUB_USERNAME]`, `[RELEASE_TAG]`, `[CODE_DOI]` and `[DATA_DOI]` in the README, `CITATION.cff` (where applicable), `docs/CODE_AVAILABILITY_STATEMENT.md` and manuscript only after the corresponding repository/release/record exists.
